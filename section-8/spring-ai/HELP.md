# Local Fact-Checking Evaluator Setup

This project uses a local AI model to act as a strict fact-checking judge (`FactCheckingEvaluator`) against responses generated by OpenAI.

To ensure the local evaluator is smart enough to handle strict logic and formatting instructions without hallucinating, we use **Bespoke MiniCheck (7B)** (`bespoke-minicheck:7b`), a model specifically fine-tuned for fact-checking and hallucination detection.

## 1. Download the Evaluator Model
Assuming your Ollama container is already running via Docker Compose, open your Fedora terminal and run the following command to download the model into your Docker volume:

```bash
docker exec -it ollama ollama pull bespoke-minicheck:7b
```

## 2. Configure Spring AI
Once the download is complete, update your Spring Boot configuration to point the Ollama Chat Client to the new model.

**If using `application.properties`:**
```properties
spring.ai.ollama.chat.options.model=bespoke-minicheck:7b
```

**If using `application.yml`:**
```yaml
spring:
  ai:
    ollama:
      chat:
        options:
          model: bespoke-minicheck:7b
```

## 3. Hardware Performance Note
This project is running on a Fedora host with an **NVIDIA GeForce 940MX (4GB VRAM)**.

Because a 7B parameter model requires roughly ~4.7GB of memory, Ollama will automatically load 4GB of the model directly into your GPU's VRAM for hardware acceleration, and seamlessly spill the remaining ~0.7GB into your system's standard RAM.

* **What this means:** The model will work perfectly and process logic correctly, but you may notice a slight delay (a few extra seconds) when evaluating the answer compared to smaller 1B/3B models. This is normal and expected behavior for your hardware profile.
